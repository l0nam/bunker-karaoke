# Бункер-оке · Karaoke Queue

Веб-приложение для ведущего караоке на Discord-сервере **Bunker Online**. Публичная страница показывает текущего исполнителя, две очереди и позицию участника. Кабинет ведущего управляет вечером, добавляет людей и треки, редактирует очередь и формирует сообщения для Discord.

## Возможности MVP

- Публичная очередь с обновлениями через Supabase Realtime.
- Подписанный HTTP-only cookie для входа ведущего и отдельная серверная проверка API.
- Поиск участников по сохранённым никнеймам и Discord ID.
- Поиск названий и обложек через Deezer и iTunes Search API.
- Полноценное воспроизведение выбранных видео YouTube во встроенном плеере — без проксирования аудио через Vercel.
- Основная и повторная очереди. Сервер определяет автоматический приоритет по истории текущего вечера.
- Добавление одного участника или списка до 100 ников одним атомарным вызовом.
- Изменение порядка, перенос, удаление, пауза/возобновление, следующий исполнитель и архив вечеров.
- Светлая/тёмная темы, адаптивная навигация, PWA manifest, standalone, 404 и общий offline-экран.
- Service worker кеширует только статические файлы/иконки и shell-страницу offline. API и маршруты кабинета не кешируются.

## Быстрый запуск

1. Установи Node.js 22 LTS и Docker Desktop.
2. Склонируй репозиторий и установи зависимости:

   ```bash
   git clone https://github.com/l0nam/bunker-karaoke.git
   cd bunker-karaoke
   npm ci
   ```

3. Запусти локальную Supabase:

   ```bash
   npx supabase start
   ```

   Если Supabase CLI не установлен, см. https://supabase.com/docs/guides/cli

4. Возьми локальные URL и ключи из вывода supabase start. Скопируй .env.example в .env.local и задай:
   - NEXT_PUBLIC_SUPABASE_URL
   - NEXT_PUBLIC_SUPABASE_ANON_KEY
   - SUPABASE_SERVICE_ROLE_KEY (только сервер, не публиковать)
   - HOST_PASSWORD (длинный уникальный пароль)
   - SESSION_SECRET (случайная строка не менее 32 символов)
   - NEXT_PUBLIC_SITE_URL (например, http://localhost:3000)

   Не коммить .env.local; он игнорируется Git.

5. Примени миграции:

   ```bash
   npx supabase db reset
   ```

6. Запусти приложение:

   ```bash
   npm run dev
   ```

Публичная страница: http://localhost:3000  
Вход ведущего: http://localhost:3000/host

## Переменные окружения

См. .env.example. Секрет SUPABASE_SERVICE_ROLE_KEY нельзя отправлять клиенту или использовать в браузерных компонентах. GENIUS_ACCESS_TOKEN необязателен: без него открывается обычный Genius Search. Поиск треков зависит от доступности Deezer/iTunes.

## Адаптация и ограничения

- Для реального запуска нужен Supabase проект, миграции и заполненные секреты. Репозиторий сам по себе не содержит ключей или данных Bunker Online.
- Пароль ведущего общий. Нет ролей, нескольких аккаунтов, OAuth-подключения Discord или журнала действий.
- Публичная очередь и поиск позиции обновляются через Realtime; при проблеме WebSocket хук перечитывает снимок очереди, но приложение должно иметь HTTP-доступ к Supabase.
- Deezer и iTunes используются для метаданных, а не для передачи аудио. Для воспроизведения ведущий вставляет ссылку на YouTube-ролик в запись участника; поиск подходящей караоке-версии открывается в YouTube. Видео должно разрешать встраивание.
- YouTube-плеер загружается только после нажатия «Слушать на сайте». Видео и аудио передаются браузеру напрямую от YouTube; Vercel обслуживает только приложение и API очереди. Плеер не запускается автоматически на устройствах посетителей.
- PWA офлайн показывает статическую страницу-состояние. Управлять очередью офлайн нельзя; приватные данные намеренно не сохраняются.
- Исторические записи до миграции архива импортируются в один legacy-набор без восстановления точных дат.
- Нет end-to-end тестов реального мобильного браузера и установочного PWA-диалога на iOS/Android. Их необходимо проверить на физических устройствах.
- Публичный домен, HTTPS, политика резервного копирования и мониторинг задаются при развёртывании.
